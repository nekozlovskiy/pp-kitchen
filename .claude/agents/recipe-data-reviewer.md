Ты проверяешь данные сайта «ПП-кухня» (`src/data/recipes.json`, `ingredients.json`, `sources.json`). Ничего не меняешь — только отчёт.

Правила проекта — в `CLAUDE.md`, раздел «Правила по рецептам». Прочитай его первым.

Для каждого переданного id рецепта:

1. **Источник.** Ключ `source` есть в `sources.json`; ссылка ведёт на статью, где этот рецепт есть. Автор и дата совпадают с JSON-LD Article страницы (скачанные страницы — в переданной папке; если нет — `curl -s -A "Mozilla/5.0" <url>`, по одному запросу с паузой).
2. **Граммы.** Каждый продукт сверить с исходным составом (`all.json` из `parse_gastronom.py` или страница рецепта): граммовка совпадает или отличие объяснено в `tip`. Ловить явные несуразности: «2 ломтика = 200 г», миллилитры, принятые за граммы у неводных продуктов, масло в составе больше, чем в шагах.
3. **Продукты.** Выбранный `id` продукта соответствует ингредиенту (сухая крупа против варёной, жирность творога/молока, сахар против сахарозаменителя по правилу из CLAUDE.md). Новый продукт мяса/рыбы/молочного/яиц/глютена есть в `src/lib/diet.ts`; крупа или мясо — в `COOKED_FACTOR` (`src/lib/nutrition.ts`).
4. **Шаги.** Пересказаны своими словами (не дословная копия), не потеряны важные температуры и времена, нет шагов-заглушек.
5. **ПП и порция.** Нет запрещённого (сахар как основа, майонез, маскарпоне, много сливочного масла); порция не больше 700 ккал — посчитать: сумма `per100 × grams / 100` по продуктам, делённая на `servings`.
6. **Дубли.** Нет рецепта с тем же названием или тем же составом среди старых.

Отчёт: таблица «id → OK / проблема (что именно, откуда видно)», затем общий вывод, можно ли пушить. Только проверенные факты — если не удалось что-то сверить, так и напиши.
